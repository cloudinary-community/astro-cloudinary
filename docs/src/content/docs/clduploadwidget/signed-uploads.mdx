Signing requests is an easy way to provide enhanced security for your file uploads. This helps
deter people from making unauthenticated uploads to your cloud.

## Configuring Signed Uploads

Setting up CldUploadWidget to sign uploads is as simple as passing an API endpoint as a prop:

<CodeBlock alwaysExpanded>
```jsx
---
import { CldUploadWidget } from 'astro-cloudinary';
---
<CldUploadWidget
  signatureEndpoint="<API Endpoint (ex: /api/sign-cloudinary-params)>"
  uploadPreset="<Your Signed Upload Preset>"
>
  <button>Upload</button>
</CldUploadWidget>
```
</CodeBlock>

However, that API endpoint needs to return a specific shape in order to properly communicate
with the CldUploadWidget.

## API Endpoint to Sign Requests

When working in Astro, we gain access to a server environment through both somewhat traditional means
and serverless functions.

This means, we can use the [Cloudinary Node SDK](https://cloudinary.com/documentation/node_integration)
in order to easily sign our requests.

To start off, install the Cloudinary Node SDK with:

<CodeBlock alwaysExpanded>
```
npm install cloudinary
```
</CodeBlock>

In order to sign our requests, we'll need to use our Cloudinary API Key and Secret, so set additional
environment variables:

<CodeBlock alwaysExpanded>
```
PUBLIC_CLOUDINARY_API_KEY="<Your API Key>"
CLOUDINARY_API_SECRET="<Your API Secret>"
```
</CodeBlock>

Then, we want to create a new API endpoint:

Create a new API route file such as `src/pages/api/sign-cloudinary-params.ts` and inside add the following:

<CodeBlock>
```js
import type { APIRoute } from "astro";
import { v2 as cloudinary } from "cloudinary";

cloudinary.config({
  cloud_name: import.meta.env.PUBLIC_CLOUDINARY_CLOUD_NAME,
  api_key: import.meta.env.PUBLIC_CLOUDINARY_API_KEY,
  api_secret: import.meta.env.CLOUDINARY_API_SECRET,
});

// Only sign the parameters your uploads need. Signing anything the browser sends
// would let anyone sign other requests to your Cloudinary account, such as deletes.
const ALLOWED_PARAMS = ["timestamp", "source", "upload_preset"];
const UPLOAD_PRESET = "<Your Signed Upload Preset>";

// Cloudinary rejects timestamps more than an hour old but accepts any future one,
// so only sign timestamps close to the server's clock.
const TIMESTAMP_WINDOW_SECONDS = 5 * 60;

export const prerender = false;

const badRequest = (error: string) => Response.json({ error }, { status: 400 });

export const POST: APIRoute = async ({ request }) => {
  let body;

  try {
    body = await request.json();
  } catch {
    return badRequest("Invalid parameters");
  }

  const { paramsToSign } = body || {};

  if (
    !paramsToSign ||
    typeof paramsToSign !== "object" ||
    Object.keys(paramsToSign).some((key) => !ALLOWED_PARAMS.includes(key)) ||
    paramsToSign.upload_preset !== UPLOAD_PRESET
  ) {
    return badRequest("Invalid parameters");
  }

  // Older Cloudinary signature versions join name=value pairs with & without
  // escaping them, so a value containing & or = could add a parameter that
  // was never checked above.
  const hasUnsafeValue = Object.values(paramsToSign).some((value) => {
    if (typeof value === "number") return false;
    if (typeof value !== "string") return true;
    return /[&=]/.test(value);
  });

  if (hasUnsafeValue) {
    return badRequest("Invalid parameter value");
  }

  const { timestamp } = paramsToSign;
  const now = Math.floor(Date.now() / 1000);

  if (
    typeof timestamp !== "number" ||
    !Number.isFinite(timestamp) ||
    Math.abs(now - timestamp) > TIMESTAMP_WINDOW_SECONDS
  ) {
    return badRequest("Invalid timestamp");
  }

  const signature = cloudinary.utils.api_sign_request(paramsToSign, import.meta.env.CLOUDINARY_API_SECRET);

  return Response.json({ signature });
}
```
</CodeBlock>

Whatever path you use will now be the value of `signatureEndpoint` for the CldUploadWidget.

The endpoint only signs uploads that use your signed upload preset, so the preset's settings
control how files are stored. If your widget uses options such as `folder`, `tags` or `cropping`,
add the parameters it sends for them (`folder`, `tags` and `custom_coordinates`) to `ALLOWED_PARAMS`.

The widget takes its timestamp from the visitor's device clock, so the endpoint only signs timestamps
within five minutes of the server's clock. A visitor whose device clock is further off than that is
rejected. Change `TIMESTAMP_WINDOW_SECONDS` if you need a different window.

Also make sure that only users who are allowed to upload can call this endpoint, for example by
checking that they're signed in.
